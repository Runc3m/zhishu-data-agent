# 业务评测

[English](evaluation.en.md) · [业务上下文](business-context.zh-CN.md)

`evals/business.py` 是独立、可公开的合成零售数据及标准答案，包含订单、退款、商品明细三张表。20 个案例各有中文和英文问题，共 40 个问题。

覆盖净收入、毛收入、已完成退款、有效订单、平均客单价、季度与月份边界、地区汇总、退款订单去重、商品关联重复计数、数量、取消订单、测试记录排除、分/元换算、缺少成本和定义冲突。

人工可核对的基础值：6 笔有效订单，毛收入 2,500 元，已完成退款 280 元，净收入 2,220 元。两个澄清案例不应生成 SQL。

## 自动回归与真实模型分开

`pytest` 使用模拟模型计划，但执行真正的只读 SQL 并逐行对照标准答案，同时检查上下文版本与修正过程。它验证程序链路，不衡量真实模型准确率，也不需要 Key。

真实评测显式运行：

```powershell
.\.venv\Scripts\python -m evals.run --live --app-storage storage --output evaluation-results/live.json
```

该命令读取指定工作空间的模型配置，使用独立临时数据，不分析已有业务数据；会消耗服务商 API 额度。也可使用 `ZHISHU_EVAL_BASE_URL`、`ZHISHU_EVAL_MODEL`、`ZHISHU_EVAL_API_KEY` 环境变量替代 `--app-storage`。不要把 Key 写进命令历史或提交到仓库。

结果记录日期、模型、源码与数据摘要、生成 SQL、实际值和通过情况；不记录 Key。数值按结果比较，而不是仅检查 SQL 可执行。澄清案例自动检查无 SQL 且有回答，措辞还需人工审阅。单次通过不能推导真实业务准确率保证。

## v1.1.0 验证记录

2026-09-12，使用 `deepseek-v4-flash` 对此标准集实测 **40/40 通过**。逐条检查了缺少成本与定义冲突的中英文回答：均说明缺失或冲突，没有编造 SQL。原始问题、SQL、结果和代码摘要见[公开评测记录](evaluations/v1.1.0-deepseek.json)。这是一个小型公开标准集的单次结果，不是生产数据准确率承诺。

## 调查回归测试（开发版）

新增 tests/test_investigation.py：实际执行合成数据 SQL 并核对人工计算的月度/品类总额；验证缺日期、重复订单/退款、空金额、异常状态和孤立退款会阻止比较。模拟规划器验证依赖上一步结果的查询、五步上限、重复停止、只读修复预算、总结失败后的证据保留、双语和导出。原有 20 道业务题及英文对应题仍保留。模拟模型通过率不等于真实模型准确率。

## Olist 与双语 RAG 实测（2026-10-14）

当前源码版、DeepSeek V4 Flash、Olist 官方历史快照，记录见 [Olist 评测证据](evaluations/insightbridge-olist.json)。

| 三种上下文方式，3 题 × 双语 | 各 6/6 | 关键词、混合、完整上下文均通过；未证明业务回答准确率提升 |

复现命令：`python -m evals.warehouse --live --app-storage storage`、`python -m evals.retrieval`、`python -m evals.ablation`。warehouse 与 ablation 会消耗 API 额度，retrieval 为纯本地测试。原始失败记录仍保留在本地 evaluation-results，包括一次无效引用；该问题修复后复测。调查解释仍可能出现过度概括，用户必须核对证据。Olist 没有真实成本和退款，不以该数据声称利润或净收入分析能力。

## 对话式 BI 回归

完整后端回归 161 项通过；格式校验与简短解释修复后的定向回归 78 项通过，前端图表数据映射 6 项通过。真实模型测试覆盖中英各三轮：宽泛排名、解释追问、决策建议，共 6/6 通过指定检查。GMV 冠军另外使用 raw_orders + raw_order_items 独立查询核验，避免订单金额连接明细后重复计数。完整记录见 [conversational-bi.json](evaluations/conversational-bi.json)。

这是六个对话冒烟案例，不是整体业务准确率。首轮发现了商品明细连接导致的重复金额，以及后续一轮模型返回错误对象被当成空计划；修复后复验通过。自然语言的每一项因果/建议仍需人工审阅；粒度校验只覆盖已知直接关联模式。

复现：`python -m evals.conversation --live --app-storage storage`（使用已保存模型配置，会产生 API 用量）；图表测试：在 frontend 中运行 `npm run test:charts`。

浏览器端另发现一次报告对象后追加字段的格式异常；最终增加首个完整对象解析与截断结论恢复，20 项相关回归通过，避免把原始 JSON 展示在对话里。
