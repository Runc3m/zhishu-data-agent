# 安装与使用

[English](usage.en.md) · [首页](../README.md)

## 启动

支持 Windows 10/11 x64。从 [Releases](https://github.com/Runc3m/zhishu-data-agent/releases) 下载 ZIP，完整解压后双击 `Zhishu.exe`，不要只复制 EXE。默认端口为 8100，被占用时自动选择附近端口。点击“打开分析网页”可重新打开界面。保留启动中心，结束时点击“退出知数”。

应用目前未代码签名。若 Windows 提示无法识别发布者，先核对来源与附带的 SHA-256 校验文件，再决定是否运行；无需关闭系统保护。

## 第一次分析

选择销售演示数据，点击建议问题。结果支持图表、可排序数据表与 SQL；同一对话可继续追问。结果工具栏下载 CSV，输入区下方导出 Markdown。右上角切换简体中文 / English，重启后保留偏好。历史文字与原始数据不会重新翻译。

## 添加数据

CSV 首行为字段名，支持 UTF-8 / GB18030，每文件不超过 20 MB、100,000 行、120 列。导入后作为 `data` 表使用。规则模式支持“预览前 20 行”和“共有多少行”；其他问题需启用 AI。

PostgreSQL / MySQL 使用只读账号连接，读取指定 Schema 的前 30 张表结构。当前不支持跨数据源查询。查询最多返回 500 行，图表最多展示 50 组，单条查询限时 8 秒。

## 数据与升级

应用版存储位置为 `%LOCALAPPDATA%\ZhishuDataAgent\storage`；源码版为项目内 `storage`。`Zhishu.exe --data-dir <目录>` 可打开已有存储，不同目录是独立工作空间。

升级前退出知数并备份整个存储目录，包括数据库和 `local.key`。解压新版后启动，不要覆盖或删除存储。分享原始 Release ZIP 给别人，不分享个人数据目录。


## v1.2.0：知数 InsightBridge

英文产品名为 **InsightBridge**，中文继续使用“知数”。现有 GitHub 地址、存储目录、健康检查标识和历史发行包文件名保持兼容。v1.2.0 Windows 包包含对话式 BI、ZIP 导入、管道调查与关键词检索；本地向量模型为源码版可选安装。

- **双语业务检索**：复用 FastEmbed / ONNX Runtime 运行本地 multilingual-e5-small，与 BM25 通过 RRF 合并排序。知识覆盖字段、指标、表结构和 ETL，最多返回 8 个检索片段；另保留口径、排除条件和关联约束。未安装模型时界面明确显示关键词降级，不在提问时自动下载。完整业务快照供历史审计使用，不再整份注入提示词。
- **多步调查**：输入框可选择自动判断、单次查询或多步调查。AI 调查最多执行 5 条成功分析查询、共 2 次修复；重复查询会停止。另有最多 3 张表的只读质量观察。180 秒软预算在下一步开始前检查，正在执行的调用可能使总耗时超过预算。
- **可检查的依据**：展开每一步查看实际 SQL、结果和截断状态；业务片段、质量观察、核对结果与停止原因保存进历史，并包含在 Markdown 导出中。
- **更准确的总结范围**：提供所有已返回行的数值概况及前 30 行样本；返回片段不是整个数据库，求总体指标仍需聚合 SQL。数字列机械求和不代表指标具有可加性。

导入 Olist 后优先选择真实仓库；否则选择“电商调查演示”。点击“销售变化调查”可运行 2026 年 8 月对比 7 月的五步调查：订单覆盖与质量、退款质量与关联、总体变化、品类贡献、追查变化最大的品类。演示净销售额为 5,890 → 4,960 元，总变化 -930 元；Electronics -1,240 元、Home +310 元、Sports 0 元，分项与总额一致。全部数据为合成教学数据。

另外两张卡演示“退款率”口径澄清和 9 月尚未导入的边界。该规则演示仅支持卡片问题；若修改演示业务定义，需要启用 AI 才会按新定义查询。普通“销售演示数据”保留原有功能。

AI 调查适用于自己的 CSV 或数据库，但自动检查只覆盖部分类型字段，不是完整数据质量审计；日期起止不能证明导入完整。模型生成的核对与原因解释仍需检查证据。真实模型效果需另行使用配置的模型评测，本地模拟模型测试不能代表真实模型准确率。

## Olist 真实数据库与实验

源码版运行 `python -m scripts.setup_warehouse --download --embeddings`（先安装 `requirements-rag.txt`），或上传 Olist ZIP 数据包。真实仓库含 13 张表和 99,441 笔订单；金额单位 BRL。数据源页可查看表级血缘、实际 ETL SQL，并创建正常对照、关联放大、漏日期、错误状态过滤、陈旧报表的独立副本。选择副本后使用“多步调查”。已注册管道允许 8 次工具行动及 2 次修复，结果保留独立核验和引用审计。

## 宽泛分析、解释与决策建议

- 问“哪个卖得最好”：默认比较已有依据的金额口径，并补充销量、订单数或趋势；回答说明默认维度与时间范围。
- 问“看不懂，解释一下”：直接使用上一轮结果，简化术语，不要求重新提供 SQL。
- 问“我该优先经营什么品类”：提供有证据的候选方向、需要验证的风险与下一步指标，不承诺利润或效果。
- 在每个结果面板切换图形或选择指标；两维数据可以显示热力图，多品类时间序列支持分组折线。每张面板可独立下载实际 CSV。

图形按返回数据选择。负数不能转换成饼图；Top N 饼图只表示返回子集；直方图统计的是查询结果的分布，不一定是原始订单分布。堆叠只适合可相加、同单位的构成项。

## 删除聊天记录

在左侧“最近分析”中，点击对应会话右侧的垃圾桶，再点击“确认删除”。只删除该会话的消息、图表和查询结果；其他会话、数据源、业务说明与 API 设置会保留。删除不可恢复，可先用“导出分析”保存副本。正在分析时不能删除。
