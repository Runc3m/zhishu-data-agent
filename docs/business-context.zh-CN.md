# 业务上下文

[English](business-context.en.md) · [首页](../README.md)

在“数据源”选择一个来源，点击预览区的“业务上下文”，填写并保存：

- **业务说明**：覆盖范围、使用约定、需要排除的记录。
- **字段解释**：按 `表名.字段` 说明显示名称、含义、单位和常见取值。
- **指标定义**：指标名称、计算公式、筛选条件和日期口径。
- **关联关系**：当前数据源内的连接字段和一对多关系，提示聚合后关联等要求。

“字段解释”下方的“从数据生成取值草稿”会读取每个字段的取值数量、范围，以及不超过 12 种取值的文本字段的实际取值，追加到输入框。草稿不会自动保存，也不会发送给模型；字段名疑似姓名、电话、邮箱、地址等个人信息时不提取取值。请删去不需要的内容，补充含义和单位后再保存。

例如：金额字段单位为“分”，净收入为已付款且非测试订单金额减已完成退款后除以 100；退款先按订单汇总，避免关联后重复计数。说明支持多行自然语言，不要求书写 SQL，也不自动翻译用户内容。

## 保存与引用

点击保存表示确认这些定义。只有内容变化才增加版本；相同内容再次保存不会增加版本。下一次 AI 分析的规划、修正和总结使用该次开始时的说明快照，切换或修改说明不会改写历史分析。

分析消息下方可展开“本次使用业务上下文 vN”，查看当时使用的完整说明；Markdown 导出也包含版本与说明。规则演示不应用业务上下文，不会标记为已采用。没有配置时保持普通问数方式。

## 已验证查询

分析结果右上角的“标记为正确”可以把这次的 SQL 保存为已验证查询。保存前把问题改写成独立、完整的问法，例如把追问“那利润呢”改成“各地区利润对比”。同一个问题再次验证会替换原 SQL；每个数据源最多 200 条。

AI 分析时，知数按字面相似度在当前数据源的已验证查询中找出最多 3 条相近问题，连同 SQL 作为参考示例提供给模型；分析消息下方可展开“本次参考 N 条已验证查询”。示例只是参考，与当前表结构或业务定义冲突时以后者为准。验证时会按当前表结构重新校验 SQL。规则演示不使用示例。在“业务上下文”窗口底部可查看和删除已验证查询。

## 边界

这是一套业务知识辅助查询机制，不是语义计算引擎。定义缺失或冲突时，模型应请求澄清；重要结论仍需核对实际 SQL 和结果。不会把模型猜测自动存为长期知识，也不开放跨数据源查询。远程 AI 会接收配置的说明，不应填入密码或 Key。

质量验证方法见[评测说明](evaluation.zh-CN.md)。
